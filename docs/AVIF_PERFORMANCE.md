# AVIF 首次使用与重复转换检查

记录日期：2026-10-27。浏览器为本机系统 Edge 156.0.4314.42；公网测试经过工作站既有系统代理，没有修改代理设置，也不代表中国大陆无代理访问。

## 已验证的原因

原实现每次点击“开始转换”都新建图片 Worker，并在该批结束时销毁。AVIF 编码器缓存保存在 Worker 内，因此浏览器虽然能缓存 WASM 文件，同页第二次转换仍会重新建立 Worker、实例化编码器。首次使用还要在点击后依次等待 Worker 与按需模块。

在基线提交 `85fde14877d785bd416088cc9994ab6ea65dcbd5` 的线上站点，本轮使用三个独立冷缓存上下文，每个上下文完成一次冷转换与一次同页暖转换。输入为本机生成的 64×48 透明角 PNG；每次都下载真实 AVIF、检查容器并重新解码。

| 地址             | 冷缓存结果出现时间（毫秒） | 同页暖转换（毫秒） | 每次转换新增 Worker |
| ---------------- | -------------------------- | ------------------ | ------------------- |
| 默认 Vercel 域名 | 1447 / 1219 / 1453         | 374 / 550 / 363    | 1                   |
| Cloudflare 域名  | 656 / 1070 / 690           | 510 / 218 / 326    | 1                   |

这轮网络较快，不能据此否认历史 5 秒用例失败：此前 Cloudflare 首次真实输出曾为 7.059 秒，另一次为 3.900 秒；历史失败日志保留在本机。基线采样最初尝试读取已销毁 Worker 的响应体，采集器出现 `Response body is unavailable`；修正为只取响应元信息后，以上重新采集的十二个样本完整通过。采集器错误没有被算作应用编码失败。

## 本批修改

- 同一图片工具页面复用 Worker 和 AVIF 实例，处理结束不再销毁；离开页面、取消或线程故障时释放。
- 用户明确选择 AVIF 后才按需准备编码器，首页与未选择 AVIF 的图片工具不请求 AVIF 引擎。不会把重模块加入首页初始化。
- 展示真实的准备状态和读取/编码阶段，不用动画伪装网络进度；准备失败可重试，失败的模块 Promise 不会永久卡住后续尝试。
- 准备与处理使用独立请求 ID。取消会结束全部等待；之后仍可新建处理器重新转换。
- Worker 消息中仅加入本机阶段与耗时，不发送到统计接口；匿名事件字段和输入不上传的约定保持不变。

页面保留一个已初始化编码器会保留相应内存，这是换取重复转换更快的取舍；取消和离开页面仍会终止 Worker。

在独立开发服务、三个冷上下文、每个上下文三次转换的九个样本中：

| 项目                          | 实测范围            |
| ----------------------------- | ------------------- |
| 首次点击到结果出现            | 118–139 毫秒        |
| 同页重复点击到结果出现        | 36–73 毫秒          |
| 页面总图片 Worker             | 每个上下文始终 1 个 |
| 选择 AVIF 后准备耗时          | 34.7–65.8 毫秒      |
| Worker 脚本启动至首条阶段消息 | 26.0–31.7 毫秒      |
| 首次读取及画布准备            | 6.0–8.8 毫秒        |
| 重复读取及画布准备            | 0.35–0.47 毫秒      |
| 首次编码及返回                | 36.0–37.0 毫秒      |
| 复用后的编码及返回            | 2.8–4.1 毫秒        |

上述本机速度不能与公网基线直接算百分比提升。能直接确定的是：原版每次都新建 Worker，修改后同页连续转换只使用一个 Worker，编解码资源不重复请求。

所有样本的 AVIF 容器、64×48 解码尺寸、透明角 alpha=0 均正确；没有页面错误，写请求仅 `/api/events`，不含测试文件名或输入内容。WASM 初始化与编码不是同一阶段：采集脚本同时记录资源请求时序、Worker 准备阶段和编码阶段；其中“最后一次 WASM 传输结束至准备完成”是含主线程消息调度的上界估计，不当作纯 CPU 初始化耗时。

已执行：

- 图片处理器生命周期、准备/处理共用、阶段消息、取消、重试和无 Worker 降级：5 项单元测试通过。
- AVIF 浏览器用例：4 项通过，包含真实下载重解码、首页不下载引擎、选择后准备、同页复用、模拟网络失败重试、取消后重新转换。
- TypeScript 检查通过。

功能用例的等待改为 30 秒以容纳不可控的冷资源传输，同时每次附加 `processingMs` 与原 5 秒预算是否满足的指标。没有把提高等待时间算作性能优化，原失败证据仍保留。

## 可复测脚本与发布后检查

运行 `node scripts/measure-avif.mjs`，默认测两个生产域名，每个域名三个冷上下文、每个上下文一次暖重复。报告默认写入 Git 已忽略的 `test-results/avif-performance.json`；可用以下环境变量指定条件：

```powershell
$env:AVIF_PROFILE_ORIGINS='https://qingxia.vercel.app,https://qingxia.aixiaolv.icu'
$env:AVIF_PROFILE_CONTEXTS='3'
$env:AVIF_PROFILE_ROUNDS='2'
$env:AVIF_PROFILE_LEAD_MS='0'
$env:AVIF_PROFILE_OUTPUT='F:/轻匣/logs/avif-published-profile.json'
node scripts/measure-avif.mjs
```

`LEAD_MS` 只用于明确记录“选择 AVIF 后等待多久再点击”的测试条件，默认为 0，不暗中预热后冒充冷转换。

发布后的默认域名与 Cloudflare 新版本采样应单独补记，不把上述本地结果当作已发布性能证据。测试流量会进入真实匿名统计，不能视为自然访客增长。

详细本机证据：`avif-baseline-profile-v3.json`、`avif-optimized-local-profile.json`、`avif-e2e.txt` 及其独立测试输出目录。早期采集器失败的原记录未覆盖。
