# 抖音解析与下载等待优化

2026-10-27。用户确认亲自解析、下载成功后，本批集中优化等待时间。保留平台原始视频、画质、实验性标识和无需普通用户登录的使用方式。

## 已实现

- 成功的公开解析结果在单个函数实例内最多保留 30 秒，同一规范化链接的并发请求共用一次平台请求。最多 50 项（包含处理中请求），失败不缓存、过期驱逐；明确的到期参数会提前结束保留时间。
- 每次请求仍先检查来源、输入和原有每分钟限流。响应继续 `no-store`，不依赖付费缓存或数据库新表。内存只暂存公开元信息和原始媒体 URL，不缓存媒体内容、不向日志或磁盘保存签名地址。
- 解析得到结果后，浏览器最多对两个经过校验的官方媒体 origin 发出匿名 `preconnect` 提示，为点击下载准备连接；不预下载视频，清空结果和离开页面时移除提示。浏览器可以选择忽略该优化。
- 下载反馈由响应流的真实接收字节驱动，最多约每 150 ms 更新一次；已知总大小显示百分比，未知总大小只显示已接收字节。保留取消、超时、200 MB 上限及完整文件校验。

## 性能口径

优化前在同一工作站、隔离 Edge、显式使用既有本机代理、默认生产域名，连续两次解析同一用户自有短链为 **2,818 / 3,651 ms**，均 200 且目标匹配。没有发起媒体下载。这是浏览器请求到收到 JSON 的实际耗时。

短期结果复用主要改善同链接在同一暖实例中的重复解析，不能承诺首次请求或不同实例同样提速。预连接主要减少连接准备等待；视频吞吐仍受平台 CDN、文件大小和用户网络影响，本批不承诺固定下载倍率，也不通过降低画质或重编码换速度。
