## 同条件性能结果

设备：Windows 11、Ryzen 7 7735H、16 逻辑核、约 15GiB 内存；Edge `156.0.4314.42`。前后均在本机生产预览 `127.0.0.1:5310`，viewport 1440×1000，DPR 1，无网络降速；常速与 4× CPU 降速各 3 个独立冷上下文。性能采样与浏览器回归顺序执行，没有并发构建。以下是各档三个样本的中位数：

| 指标                                     | 常速升级前 → 后    | 4× CPU 升级前 → 后 |
| ---------------------------------------- | ------------------ | ------------------ |
| 首页 ready（标题、搜索、工具卡片可操作） | 213 → 233ms        | 983 → 1062ms       |
| FCP / 固定窗口 LCP                       | 194 → 233ms        | 799 → 807ms        |
| 搜索输入到结果与下一帧                   | 4.36 → 5.78ms      | 27.10 → 31.05ms    |
| PNG→真实 AVIF 按钮就绪                   | 137 → 149ms        | 251 → 349ms        |
| 脚本滚动 rAF 间隔 p95                    | 6.095 → 6.100ms    | 约 6.09 → 6.09ms   |
| 首页 transfer 字节                       | 118,663 → 131,608B | 相同资源集合       |

新版常速 ready 范围 225–269ms，LCP 范围 195–407ms；4× CPU ready 为 1061–1069ms，LCP 为 799–807ms。装饰和排版有实际开销，首页 transfer 增加 12,945B（约 10.9%）。尤其 4× CPU 的 AVIF 小样本就绪中位数增加约 98ms（39%），保留此变化，不宣称处理性能全面提升，也不能仅凭本轮小样本将变化因果完全归于场景。

六次新版样本均无 >50ms 的滚动 rAF 间隔，无页面错误；首页 PDF、FFmpeg、AVIF 编解码等重引擎请求为 0。六次真实 AVIF 下载均通过容器、64×48 重解码和透明角 alpha=0 检查，测试输入未上传。

复测脚本为 `scripts/measure-visual.mjs`，使用 `VISUAL_PROFILE_URL`、`VISUAL_PROFILE_OUTPUT`、`VISUAL_PROFILE_LABEL`、`VISUAL_PROFILE_CPU` 和 `VISUAL_PROFILE_CONTEXTS` 明确指定条件。原始 `before-metrics.json`、`after-final-metrics.json`、`final-performance-comparison.json` 留在仓库外原日志目录。

限制：LCP 为首次输入前固定 1200ms 窗口，搜索响应不是浏览器真实 INP；rAF 是渲染调度代理指标，不能当作合成器 FPS。4× CPU 是实验室条件，不能代表真实低端手机。没有将公网与本地结果直接算提升，也没有把代理网络速度归为页面 CPU 性能。
