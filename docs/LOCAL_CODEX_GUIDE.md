**2. 确认真正的本地仓库，保护现有文件。**

`F:\轻匣` 是用户的本机工作目录，可能同时放着代码、密码工具和日志，不保证该目录本身就是 Git 根目录。先检查目录及现有检出，找到 `origin` 指向本仓库的真实 Git 根目录。只有确认没有现有检出时，才克隆到独立的新子目录。

在真实仓库根目录依次执行：

```powershell
git rev-parse --show-toplevel
git remote
git status --short
git fetch origin main
git log --oneline --decorate -6
```

读取 origin 核验仓库身份时，先脱敏用户名、密码和令牌，不直接输出可能带凭据的远端 URL。检查并保留本地未提交文件和本地提交，再决定同步方式。干净且可以快进时使用 `git merge --ff-only origin/main`；存在分叉或冲突时先调查，不能 `reset --hard`、强制推送或覆盖用户工作。开发使用普通分支，例如 `dev/p1-fun-tools`；不默认创建第二个 worktree。

以下是本机私密工作材料，不是网站源码：

- `F:\轻匣\private\admin-password.dpapi`
- `F:\轻匣\打开站长密码.cmd`
- `F:\轻匣\scripts\view-admin-password.ps1`
- `F:\轻匣\logs\` 及其中的会话、运行和截图材料
- `.env.local`、CLI 凭据、浏览器会话和其他私钥

核对 Git 忽略规则；若上述材料位于仓库内，为它们配置准确的本地排除规则，不能忽略整个应用 `scripts/` 目录。不要执行未经检查的 `git add .`。提交使用明确文件路径，并检查暂存差异。

**4. 建立 Windows 开发基线。**

使用 Node.js 24.x、npm；依赖以 `package-lock.json` 为准。先在本机实际运行：

```powershell
node --version
npm --version
npm ci
npm test
npm run build
npm run test:e2e
```

Playwright 找不到浏览器时，可以安装其 Chromium：

```powershell
npx playwright install chromium
```

也可复用已安装的 Edge/Chrome，例如实际路径存在时：

```powershell
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE = 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
npm run test:e2e
```

不要假定示例路径一定存在。命令级 npm 镜像下载失败时先诊断；需要时仅对该命令使用官方 `https://registry.npmjs.org`，保持 TLS 和锁文件完整性校验，不关验证、不随意改全局配置。

开发命令为 `npm run dev`，本地 API 由 `scripts/dev-api.ts` 接入。`predev`、`prebuild` 会准备 FFmpeg、PDF 字体和许可证资源。保留 `worker.format = 'es'`、FFmpeg 的 `optimizeDeps.exclude` 和现有隔离响应头。不要手工把 `dist`、`node_modules`、生成的 FFmpeg/字体资源或 `.tsbuildinfo` 提交到 Git。

浏览器套件不要并发启动到同一输出目录，避免 `test-results` 相互清理。如果确实独立并行，分别指定 `--output` 目录并隔离服务/cache。

**5. 默认先完成线上健康复核，修复必要问题。**

分别检查自定义域名与默认域名：首页、直接工具路由、资源加载、未登录后台 API、真实后台会话、退出及缓存响应。只在有必要时安全登录；普通用户工具无须账号。

确认私有响应 `Cache-Control: no-store`，经 Cloudflare 时保持动态处理；Cookie 保留 HttpOnly、Secure、SameSite=Strict。不能为了排查方便公开统计接口、移除限流或给匿名角色开放数据库权限。

通过实际 Vercel 记录核对当前生产部署、源码 SHA、状态和运行错误。交接报告有一次 Node `DEP0169` 告警，先定位到具体依赖/调用路径和影响，再判断修复；不要因此盲目升级全部依赖或将正常接口宣称为故障。

查询 Supabase Cron 的实际执行记录，例如 `cron.job_run_details`，确认是否已经到过计划时间、最近结果和错误。`qingxia-retention-cleanup` 计划是 UTC `17 19 * * *`，即北京时间每天 03:17。不能只因任务 active 或日期已过去就声称执行成功。不要清空统计表来验证清理；数据库测试用回滚事务和有标识的临时测试数据。

Cloudflare 仅对轻匣启用的 `qingxia-disable-rum` 规则需要保留，不影响其他域名。不能重新注入 RUM/第三方追踪来测性能。DNS 与代理正常不等于大陆访问已经可靠。

**6. 先排查 AVIF 首次使用性能，再作有证据的优化。**

重点文件：`src/lib/image-client.ts`、`image-worker.ts`、`image-process.ts`、`src/tools/images.tsx`、`tests/e2e/files.spec.ts`。

分别在默认域名、Cloudflare 域名测量冷缓存与暖缓存；区分资源传输、Worker 创建、WASM 初始化、实际编码、结果显示和下载耗时，检查是否重复创建编码器、重复请求或错误重试。保存至少若干次样本、设备/浏览器、缓存与代理条件，不能只挑一次最快结果。

优先复用实例、按需加载、明确加载进度、取消和重试、合理缓存，并评估能否在用户进入工具或选择 AVIF 后适度预热；不能让首页默认下载所有重引擎。继续检查真实 AVIF 容器、重新解码、尺寸、透明度以及输入不上传。

保留原 5 秒用例的失败证据。若经测量确认其将不可控网络冷加载误当成固定 CPU 性能要求，可有依据地拆分功能等待与性能基准、设置合理超时，并保留可追踪的性能指标；不能只删断言或提高超时就声称优化成功。

**7. 独立推进抖音真实链路，不让它阻塞其他开发。**

重点文件：`api/resolve.ts`、`api/_lib/douyin.ts`、`src/tools/douyin.tsx`、`tests/douyin.test.ts`。

先使用有权测试的真实公开视频和图集，在实际部署环境观察：分享文案提取 → 短链跳转 → 公开页面响应 → 媒体信息提取 → 正确作品 ID 匹配 → 直链有效性 → 浏览器 CORS 下载。逐阶段区分网络错误、内容删除、登录/挑战、页面结构变化和下载跨域，不能将所有 422 都认定为同一原因。

可以修复公开页面格式兼容、作品 ID/图集解析、错误分类、超时和用户体验，并补实际数据形状的脱敏 fixture 测试；不把真实签名直链、完整用户分享链接或请求凭据存入仓库/日志。

**8. 默认下一批实现六类 P1 趣味工具。**

用户已同意首发 P0、随后加入趣味工具。完成上述必要修复和有边界的调查后，直接实施这六类工具，无须再让用户选择技术方案。每个都保持纯本地、无需登录、中文、桌面/移动可用；视觉沿用现有墨绿/浅色主题，交互漂亮流畅，兼顾键盘和减少动态效果偏好。参考 `docs/design/` 与 `docs/screenshots/`；需要时可生成额外界面/组件参考，但最终应是真实可交互组件，不用截图代替页面。

**9. 新增工具必须完整接入，而不是只增加一个页面。**

按现有模块结构新增独立文件，避免重工具进入首页包。每新增一类工具都检查：

1. `src/lib/registry.ts`：稳定工具 ID、中文名/说明、分类、关键词、图标和本地处理标识。
2. `src/App.tsx`：懒加载路由；首页、分类搜索、收藏和最近使用正常。
3. `api/_lib/core.ts`：同步扩展允许的工具 ID，否则匿名使用事件会被后端拒绝。
4. 如新增“趣味工具”分类，导航、工具卡片、关于页面等同步使用真实元信息和数量。
5. 复用 `ToolUI.tsx`、文件 helper、既有主题和错误样式，不各造一套交互。
6. 统计事件只发送允许的工具标识/结果，按实际操作计数；不因动画帧、组件重渲染或每个按键刷次数。

六类趣味工具本身通常不需要数据库结构变化。若确需迁移，新增版本文件、先验证并保持新旧部署兼容，不改写已应用迁移或破坏已有真实统计。

**10. 再推进剩余 P1，按小批次交付。**

默认顺序是轻量本地工具在前、重型格式转换在后。避免为一个重功能阻塞整站，可复用已有底层能力，不能做只有标题或按钮的占位工具。

- 图片/文件：EXIF 查看与清除、HEIC 转 JPG、SVG 转 PNG、图片转 Base64、批量重命名。SVG 输入不得作为任意 HTML/脚本直接注入页面；批量重命名可用 ZIP 导出，不能假装浏览器已修改用户磁盘原件。
- 文本与开发：Markdown 转 HTML、表格转 Markdown、中英文自动加空格、简繁转换、拼音、大小写、查找替换、字数、JSON 转 TypeScript、SQL 格式化、JWT 解析、URL 参数、User-Agent、Cron、HTTP 状态码。Markdown 预览应处理不可信 HTML；JWT 解析不等于签名已验证；正则测试隔离执行并设置超时，避免恶意表达式卡死页面。
- 生成/校验：条形码、密码强度、文件哈希校验、ZIP 打包/解压、文件大小格式化。复用已有密码/Hash 工具，尽量不重复造功能；ZIP 限制条目、展开大小和路径，避免无限解压或路径穿越。
- PDF：加水印、凭已知密码加解密、旋转/删除/排序、文字提取、页码/页眉页脚、签名。图片化、表单、数字签名和字体问题需要明确说明；手写签名贴图不宣称为证书数字签名。
- 媒体：视频压缩、裁剪/截取、封面、音频格式转换与裁剪。保持本地、按需引擎、取消和资源限制；压缩不承诺必定变小。

P2 的更多平台解析、Office/PDF 重转换仅在 P1 稳定后评估，不为凑工具数量突破免费、本地或隐私边界。架构或编解码能力不支持的功能，要说明具体限制而非伪装输出格式。

**11. 始终保留原产品边界。**

普通用户不增加注册、登录、会员、积分、评论、社区、推荐流、广告；站长独立后台是已授权例外。不要接入付费 AI 或 token 功能。浏览器本地工具绝不上传文件或输入正文；链接解析单独标记，只接收 URL。

以下工具明确不做：文本对比；独立图片裁剪/旋转/缩放；批量图片加水印；长图拼接；九宫格；世界时钟/时区转换；纪念日倒数；BMI/热量；个税/房贷/五险一金；汇率；亲戚关系；今天吃什么；随机姓名/网名；Lorem Ipsum；占位图；Favicon/ICO 转换；渐变色；CSS 阴影；圆角生成器；任何 AI 生成/改写/摘要/翻译。

边界说明：图片压缩/转换里的尺寸参数、视频抽帧输出分辨率继续保留；P1 PDF 页面旋转、PDF 加水印继续允许，它们不等于上述被排除的独立图片工具。时间戳维持现有北京时间/秒毫秒转换，不扩成世界时钟。

**12. 每批验证具体结果，再发布。**

一般流程：修改点相关测试 → TypeScript/生产构建 → 必要的浏览器功能与隐私测试；有新失败就定位，不反复无变化重跑，也不把零测试或跳过当通过。

对六类趣味工具，至少验证输入边界、随机数范围/去重、权重算法、动画最终显示、复制、历史/收藏刷新保留、清空、全屏退出/Wake Lock 降级、320/390px 布局与键盘操作。随机分布的单次样本不能“证明公平”；采用确定性边界和无偏算法测试，统计模拟只能作补充。

对文件工具，实际重新打开输出或验证容器/像素/页数/音轨；不能只看下载按钮或文件扩展名。继续验证前端请求不包含文件/正文，日志不记录完整媒体直链。

生产预览可在一个终端运行：

```powershell
npm run build
npm run preview -- --port 5180 --strictPort
```

然后另一个终端：

```powershell
$env:PLAYWRIGHT_BASE_URL = 'http://127.0.0.1:5180'
npm run test:e2e -- --output test-results/production
Remove-Item Env:PLAYWRIGHT_BASE_URL
```

静态预览不等于 Vercel 私有 API 已验证；后台需要在有 API 的开发环境或实际部署环境另验。检查过的端口/进程才可结束，不关闭用户其他项目。

**13. `main` 推送是生产发布，控制每次上线。**

在开发分支完成可审查的小批次，记录改动、测试结果和上一正常版本。分支预览可先验收；检查通过后正常合入并推送 `main`，不强推，不为部署成功篡改测试。每次提交只包含明确文件，发布前检查没有私密文件、生成产物和未解释的锁文件变更。

然后从 Vercel 确认 READY、实际 Git SHA 与本次提交完全一致；验证默认域名和自定义域名上的变更以及私有接口保护。不能仅凭 Git push 成功就宣布网站已更新。失败时保留错误和诊断，必要时使用平台上一正常部署或 `git revert` 恢复，不回退用户无关工作。

线上验收流量会进入匿名统计，记录测试时段和口径；不清空真实历史，也不把自动化流量称为自然用户增长。访客仍指同浏览器每日匿名去重，多日为日 UV 之和。

不改动无关域名、Cloudflare 全区设置、现有 RUM 排除规则、密码或云套餐。确需变化先说明影响范围，在用户已授权的免费开发/发布范围内执行。

**14. 大陆访问测试和每批交付记录。**

如本机处于中国大陆，先核实当前浏览器/系统是否经代理；在明确无代理的条件下检查主页、AVIF、PDF 字体和约 32 MB FFmpeg 引擎。记录网络、浏览器和缓存条件；没有独立运营商/真实手机条件时就标为未验证，不假装移动视口等于真机。不要擅自修改用户全局代理或 VPN。

每批交付给用户简短中文说明：实际改了什么、可访问的工具/页面、测试通过/失败/未执行、部署 SHA/状态、剩余阻塞。长证据和不含秘密的记录放 `docs/`；本机敏感日志留在私密目录。

更新待办状态，确保文档区分当前事实与旧报告。不要把失败结果写成成功，不把已保存配置写成已经执行，不把“存在 URL”写成文件真实可下载。

**默认执行顺序：确认仓库与秘密隔离 → 本地基线和线上健康 → AVIF 诊断/优化与抖音可行性调查 → 完整实现六类趣味工具 → 小批次验证发布 → 再扩展其余 P1。** 其中独立事项可以并行；外部阻塞只阻塞依赖它的工作，不停止所有开发。
